PandaSign Feature

Native eSignature feature integrated into Panda CRM, WebTrader & Mobile app. Fully integrated, customizable alternative to third-party tools like DocuSign.

Panda Trading Systems

Project Type

Section 01 — Problem Statement & Goals
Challenge

1) Clients relied heavily on third-party tools like DocuSign — expensive, disconnected from internal CRM workflows, and lacking visual customization.

2) Building PandaSign natively targets lower operational costs, full UX ownership, and seamless CRM integration.

Main Goals
check_circleSave company revenue by completely eliminating third-party licenses.
check_circleEnable end-user signing (interactive fillable fields + digital signature simulation).
check_circleAchieve seamless B2B CRM workflow integration.
check_circleMaintain unified design consistency across Web and Mobile.
check_circleSupport multilingual configurations and LTR/RTL rendering out of the box.
My Responsibilities
Delivered end-to-end UI/UX architecture for new features, data configurations, and client onboarding flows across CRM, WebTrader, and Mobile App.
Designed core web/mobile interface layouts, wireframes, and UI components while maintaining strict cross-platform parity within each platform's independent design system.
Collaborated daily with Product Managers and Engineering teams, managing the full design-to-QA handoff lifecycle and rapid prototype iteration cycles.
My Role

As the sole Product Designer on this initiative, my core mission was to seamlessly architect and integrate a brand-new, complex native eSignature utility into pre-existing ecosystem platforms. I had to strictly preserve core business logic while respecting and leveraging the independent, distinct design systems of each target platform, delivering highly intuitive prototypes optimized for rapid engineering implementation.

Section 03 — CRM Configuration Flow (B2B Admin Interface)

A new "PandaSign" entry was implemented into the eSignature configuration dropdown within CRM core settings.

When enabled, an "Active" toggle appears, and "Use Sign Online" becomes available across automated workflows or manual requests.

zoom_in
CRM Document Creation Methods

To provide maximum flexibility for B2B workflows, the system allows users to initiate and create automated documents via two distinct paths:

01Workflow Task (Automated)

Integrated into the standard task engine. When "Use eSignature" is checked, the task transforms into an automated document generation workflow with the following system logic:

  • •CRM Dynamic Fields: Automatically pulls internal system variables (like {{first_name}} or {{account_no}}) directly from the database into the template.
  • •End-User Fields: Supports configurable fields (Text, Number, Date, Signature) that the final recipient must complete manually.
  • •System Actions: Includes an "Add" button to instantly inject field tokens into the document schema and a "Preview Document" action for real-time verification.
zoom_in
02Manual Document Request (Client Detail View)

A lightweight manual trigger initiated directly from the client's profile. While it utilizes the same core backend editor engine, it focuses purely on on-demand generation and excludes automated CRM workflows.

  • •Client Profile Trigger: Accessed instantly via a dedicated action button inside the specific Client Detail View.
  • •End-User Field Mapping: Focuses entirely on fields completed manually by the recipient (Text, Number, Date, Signature), completely removing the "Add Field" option for dynamic CRM tokens.
  • •Dedicated Canvas & Footer: Features an isolated document workspace with a specialized section at the bottom for custom, one-off document notes and legal disclaimers.
zoom_in
Section 04 — End-User Platforms (WebTrader · Client Area)

End-users securely sign requested documents via the Verification Center on WebTrader or Mobile App.

01Verification Center List View

Displays document type as the main title with secondary subtitles (e.g., "Sign the requested document online"). Features a prominent "Sign Online" CTA.

02Document for Sign (Inner Screen)

Contextual tooltips guide users to their first interactive input field. A persistent input bar remains focused at the bottom of the screen to streamline data entry.

03Signature Input System

Users draw their signature in a scaled canvas or choose auto-filled name simulation in an uneditable "Caveat" handwriting font. Features Next/Previous step actions, an "Edit Document" review, and "Complete Signing" which pushes status to "Pending".

zoom_in
Mobile Application Integration
Mobile App Adaptation

Adapted the full end-to-end signing wizard into a touch-first mobile interface. Focused heavily on minimizing cognitive load on smaller viewports, optimizing input fields for mobile keyboards, ensuring strict biometric compliance overlays, and designing a natural thumb-zone signature canvas for effortless execution on the go.

PandaSign consolidated separate B2B admin configurations and B2C user flows into a unified product feature. It proved the business value of replacing third-party dependencies with proprietary assets, and highlighted the critical role of scalable design systems across cross-functional R&D teams.

It also served as a real-world stress test for our pre-established design systems; seeing how pre-built tokens and components drastically accelerated the design phase and streamlined developer handoff truly emphasized the immense value of scalable design infrastructure.

B2B SaaS WebTrader Platform 2.0 Redesign

A comprehensive 7-month platform overhaul of Panda Trading System's flagship WebTrader product, paired with a scalable multi-brand design system engineered for white-label deployment at speed.

Product Designer (UXUI)

Section 01 — The Challenge
The Problem

The old trading platform was difficult for users because it lacked visual hierarchy and clear navigation. Complex trading data was messy and hard to read. Additionally, the system was not scalable — customizing the interface for different partner broker brands required manual, slow code updates.

zoom_in
Section 02 — Strategic Goals
Goals
check_circleOptimize layouts for trading clarity and high-density data readability.
check_circleDevelop tokenized multi-brand scaling for white-label broker deployments.
check_circleDesign highly responsive layouts for Desktop Wide (1920×1440) and Laptop (1366×1280).
check_circleRe-architect the onboarding matrix into a guided, low-friction flow.
check_circleImplement native RTL mirroring for Arabic and Hebrew market readiness.
Section 03 — My Role & Design Process Overview
My Role

My role in the project involved redesigning the onboarding questionnaire flow. I created an adaptive design system for the platform, which included color styles, font styles, and support for dark/light modes and RTL (right-to-left) language compatibility. I worked on the main platform screens, developed responsive views for all devices, and provided developers with optimized files for rapid implementation on Zeplin, along with CSS files for styling.

Design Process

I collaborated closely with product managers and developers to understand platform constraints, user behavior, and feature priorities. I started by analyzing existing workflows, mapping user journeys, and identifying pain points. I created wireframes and low-fidelity prototypes to validate interaction models, then moved on to high-fidelity UI design in Figma using a modular system for brand themes and reusability.

Findings

The platform lacked a consistent color and font system, leading to confusion, missed elements, and extended adaptation times.

Solution

Created a style palette adaptable to both light and dark themes, preparing the CSS file with the Figma plugin "Global Style to Code" for seamless developer implementation. The light and dark themes share the same style names, allowing for quick switching and smooth integration.

Benefits

This streamlined both design and development, significantly reducing adaptation time while maintaining platform functionality.

Section 04 — Design System & Scalability

Developed and maintained a design system tailored to WebTrader's needs, including components, UI tokens, themes, and layout rules. The system supports multiple brands with different color palettes and font rules, while ensuring consistency and maintainability. I worked closely with developers to deliver Figma specs and assets via Zeplin, ensuring smooth handoff and pixel-perfect results.

lightbulb Case Study in Point — Resolving Team Component Chaos (Real-World Challenge)
Context

Because this was a highly customized product, every single interface element required a huge number of layout variants based on component sizing and specific contextual use-cases across multiple dense pages. All core components had to be strictly engineered in two separate responsive target viewport sizes: Desktop Wide (1920×1440) and Standard Laptops (1366×1280).

The Friction

Due to rapid feature delivery timelines, two designers worked in parallel on separate application modules without a strict initial sync protocol. This resulted in a massive, redundant overhead where duplicate and conflicting components were generated for the same layout patterns, completely confusing the engineering teams and stalling the handoff.

My Action

I took the initiative to audit, consolidate, and clean up the entire cross-module library. I organized intensive cross-functional alignment workshops between the design team and R&D leads to define optimal UI states. I then refactored the chaotic layouts into a unified, clean component library with strictly documented variants.

The Outcome

While starting production without a fully locked system framework initially cost extra refactoring cycles, it saved hundreds of hours during development. I established a logical component framework that bridged the gap between design and development, drastically reducing future engineering technical debt and gaining deep experience in large-scale system architecture.

zoom_in
Section 05 — User Challenges in Onboarding Questionnaire

The second step was understanding user issues with the onboarding questionnaire. Through user feedback, we identified usability problems, leading to key design improvements that enhanced the questionnaire flow and UI clarity.

Problems
warningThe legacy onboarding questionnaire appeared as an intrusive pop-up canvas over the core workspace.
warningOn the login screen, a confusing secondary CTA labeled "Join Us" redirected users back to the registration page, disrupting the access loop.
warningWhile the main signup container held all necessary fields, its presentation layer was entirely outdated.
warningMost critically, the onboarding flow relied on massive dropdown chains and heavy scrolling, creating a cumbersome, high-friction user journey.
zoom_in
Solution

To enhance user convenience, the onboarding process was restructured from a cluttered pop-up to an isolated, step-by-step flow following the "One Question per Page" pattern. A clear progress stepper and welcoming contextual pop-ups were added, allowing users to save their progress and return later, simplifying the user journey and accommodating brand-specific question sets.

Benefits

This redesign not only allows for faster completion of the questionnaire but also provides the option to save progress, enabling users to return to the platform and continue seamlessly. Additionally, it enhances user engagement and satisfaction through a more intuitive interface.

zoom_in
Section 06 — Platform Features Evolution
Scaling the Ecosystem

Successfully scaled the ecosystem by designing and integrating next-generation interactive modules directly into the unified interface. This included architecting the Service Desk Chat module (seamlessly bridging WebTrader utilities, underlying CRM states, and touch-optimized mobile screens), embedding third-party analytics hubs like TipRanks for live market data feeds, and creating minimal, low-friction 2FA security validation flows.

City Fix

Mobile application for urban improvement and infrastructure optimization. Designed for multi-generational B2C users to streamline civic problem reporting.

Company / Client
Private Client
Timeline
3 Weeks
My Role
Mobile UX/UI Designer
Project Type
End-to-End Mobile App
Platform
Android (Material Design)
Tools
Figma, Material Design, Android UI Kit, Mobile UX
Section 01 — Problem Statement & Goals
Challenge

Designing a civic service app on tight technical specifications that must remain highly intuitive for users of all age groups — from tech-savvy youth to elderly citizens. Filing a traditional city complaint was slow, bureaucratic, and lacked transparency in resolution status.

Goals
check_circleSimplify and accelerate the issue-reporting pipeline via mobile devices.
check_circleIncrease transparency by allowing citizens to track real-time resolution status.
check_circleBoost civic engagement and accelerate urban improvement cycles.
check_circleLeverage native Material Design components, typography, and spacing for familiar UX.
zoom_in
Section 02 — Core Features & Functionality
Secure registration and verification via phone number.
Frictionless, 3-step reporting flow to submit a city infrastructure problem.
Real-time proposal and ticket status tracking dashboard.
Integrated online support chat for immediate assistance.
Photo-evidence reporting showing "Before / After" resolution states.
Personalized profile configuration and notification management.
Section 03 — User Research & Competitor Analysis

Conducted a comprehensive competitive analysis to evaluate industry benchmarks — mapping user journeys, application cost structures, authentication onboarding friction, primary task velocity, ease of use across diverse age groups, and support accessibility standards.

Main issues found in competitor apps:
Complex Registration
Too many steps and mandatory phone verification before users can even see the main screens.
Confusing Home Screen
Too many buttons and irrelevant services make it hard to find basic actions.
Too Many Steps to Report
Sending a simple issue ticket takes more than 5 separate screens.
Hard to Read & Click
Small text size, low color contrast, and tiny buttons that are hard to tap on mobile.
No Status Updates
People have no idea what happens to their request after submitting it.
No Direct Support
No in-app chat or clear way to ask administrators for help.
Section 04 — From Sketches to Components

We started with quick low-fidelity sketches and wireframes to test layout patterns and button placements. Once the structure was clear, we built a modular design system in Figma with accessible colors, custom icons, and flexible UI components.

Section 05 — Outcomes & Impact
Impact
trending_upSimplified ticket submission: Reduced the reporting flow to 3 clear steps with photo uploads and automatic GPS location.
trending_upFrictionless onboarding: Users can now explore city services right away without being blocked by mandatory phone verification.
trending_upClear status tracking: Added real-time tracking and push notifications so citizens always know when their issue is being fixed.
trending_upAccessible design system: Built a cohesive Figma component library focused on high readability, strong color contrast, and clear touch targets.
